# 小家台球室

入口：小家桌面 → 娱乐室 → 台球室。选择任一伴侣即可开始休闲八球；拖动瞄准，按住蓄力，松手击球。桌边聊天支持文字和已有音色的消息朗读。

每次进入默认开启“读出新消息”和“瞄准线 + 假想球”。朗读使用聊天室对应角色配置的音色，仅播放新到的伴侣消息；历史记录不重播，消息行不再显示单独的“听”按钮。

瞄准时拖动白球的球杆一侧，虚线与假想球显示在手指的另一侧；点击会先转动球杆，随后继续拖动微调。聊天面板增高并略向上抬，底色半透明；点面板外的空白处关闭，关闭点击不会传到球桌。面板不再提供“收起”按钮。

聊天图标旁的小麦克风无需展开聊天，手机放在下方方便拇指按住：按住录音、松手转文字并直接发送给本局对手，向任意方向滑开 60 像素后松手取消，短于半秒不发送。使用聊天室相同的 `/api/voice/transcribe` 和当前语音识别配置；手机应用复用 `AionAudio` 原生录音，浏览器使用 MediaRecorder。离开页面会停止录音和本页朗读；识别后发送失败时把文字放回聊天输入框，方便重试。浏览器录音需要 HTTPS 或本机 localhost，手机应用走已有原生桥。

绘制缓存静态桌面纹理，静止时不再重画；力度数值和聊天/操作区只在变化时更新，隐藏子页暂停绘制。击球物理步长及算法未改动。390×844 Chrome 同一试玩场景对照：静止 4 秒从约 235 次绘制、2184 次 DOM 变动降为 0 次，主线程任务耗时约 328 → 43 ms；这不是手机真机帧率。

手机竖屏时球桌纵向显示，视口裁去桌外空白并紧接顶部信息栏，不拉伸物理桌面；球号保持正向，触摸按完整画布坐标换算。头像、花色、比分与局数合为一条，名字沿用配置。手机只保留一层深绿桌框，去掉外围矩形底板和常驻规则文字，规则仍可在“玩法”查看。下方左侧是一组圆形微调键，中间为语音/聊天小图标，右下角是圆形蓄力键；控件留在球桌外，不遮住球袋。蓄力时球杆随力度后拉，在旁边显示小进度和正向百分比，松手或取消后消失。手机新话在桌子下沿中央显示半透明、最多两行的小气泡（约 12 秒），带配置中的发言者名字，同一时刻仅显示最新气泡；点气泡或聊天图标展开完整记录。横屏和桌面继续横向显示球桌。娱乐室采用独立日夜配色、紧凑双列入口和固定返回栏。

伴侣出杆前，后端先保存本杆的算法选择，再等待约 2.5 秒模拟反应；网页使用同一份方向和力度演示转杆瞄准、后拉和出杆，不重新计算击球。预览本身不接受/执行一杆，实际动作仍由服务端一次提交；暂停或恢复会取消旧预览，已接受的一杆继续按原有存档规则结算。双方伴侣自主对局的两个位置都支持该动画。

## 文件与运行

本目录自带复制的物理、规则、算法、画面和音效；不引用原 demo 路径。大厅放在旁边的 `entertainment` 目录。后端复用小家的 Python 环境，击球算法需要 PATH 中的 Node.js，无新增 Python 运行依赖。更新后重启小家后端、刷新页面即可。

球局存档在现有 `DATA_DIR / billiards`，每局独立 JSON。保存包含球位、分组、轮次、已赢局数、连续表现、桌边消息和待结算动作。出杆先保存动作再结算；重复提交或刷新不会重复计分。已接受的一杆先结算到停稳位置，然后暂停。服务重启后用户球局保持暂停，双伴侣运行中的球局恢复后台执行。

## 聊天与自主约球

模型沿用现有人设、名字和模型配置，继承现有日常聊天上下文，仅生成聊天。每次调用带上当时已结算的真实球况，普通出杆不调用模型；连进、连续失误、犯规、黑八阶段和胜负提供接话机会，通常间隔至少 35 秒。模型慢或失败时仍能打球。桌边对话只写入台球存档，不新建私聊/群聊，也不逐句写入日常记录。

每局真实分出胜负后，自动把一张战报卡片发到用户最后发消息的现有窗口（主 AI 私聊、另一位伴侣私聊或群聊）。按用户消息时间确定目标，忽略旧 `billiards_` 自动会话，避免 AI 回复、空会话或启动恢复时间抢走投递目标。卡片包括配置中的双方名字、胜负、累计胜局、杆数与结束原因，并带 `system_model_context` 标记，后续聊天可读到结果。稳定消息 ID 与同事务跨端同步保证重载/重试不重复发送；每一局独立一张，已发送的旧版历史战报不批量回灌。局终战报也继续发布至家庭动态。

台球音效整体增益为原来的 2 倍，音量滑杆和静音仍有效；高音量及多个音效同时响时限制总输出在可播放范围内。该调整只作用于台球音效管理器。

在“家庭动态”的自主行动设置中，为两位伴侣开启“邀请另一位家庭成员打一局休闲台球”。该新行动默认关闭，沿用原自主行动调度；对方可接受或婉拒。成局后不依赖网页继续打，你可以旁观、加入桌边聊天、明确暂停或结束。已有未结束球局的参与者不能同时开另一局。

用户参加的球局在离开页面、切出应用或窗口控制失效后暂停；回来点击“继续”。两个窗口只有一个可以出杆。“结束球局”释放参与者，保留比分与聊天；“再来一局”延续双方已赢局数。

## 可选模块隔离

宿主仅增加可选路由/生命周期、自主行动入口、资源清单和大厅导航。缺少模块时捕获安装错误；缺少 Node 时仅台球不可用；算法错误暂停当前局；模型错误只影响接话。Android 缓存只有在台球路由安装成功后才纳入台球资源，避免可选模块的 404 阻塞其他页面更新。未使用台球时不创建存档、不启动球局任务或调用台球模型。

## 验收

- `python -m unittest discover -s billiards/tests -p "test_*.py" -v`：19 项关键测试通过（在 `aion-chat` 内运行），包含桌边对话不访问日常数据库、三个窗口投递、局终卡片去重、中断恢复和 AI 预览与实际方向一致。
- `node --test billiards/static/tests/*.test.cjs`：原算法/控制/音效测试及竖向坐标、球杆侧瞄准、卡片名称转义、音效增益和远程球杆预览用例，87 项通过。
- 13 项宿主系统通知渲染测试通过；实际私聊/群聊系统消息渲染函数在手机尺寸、日夜主题下展示单张小卡片，无脚本异常。
- 隔离 FastAPI 试玩服务 + Chrome：真实拖动/蓄力操作、出杆中刷新只计一杆、两窗口控制、暂停续玩、离开网页后的双伴侣后台出杆通过；无浏览器脚本异常。
- 桌面、390×844、360×640 和 450×970 竖屏、844×390 横屏检查通过；390×844 实际可见球桌约 664 像素高，360×640 约 460 像素高（已扣除裁去的画布空白），触摸放置、瞄准、SVG 微调键、圆形蓄力键、蓄力显示/取消与出杆验证通过。折叠聊天和头像气泡使用模拟新消息做浏览器验收；应用前后台回调会暂停用户球局。
- 浏览器和原生录音桥模拟验证：聊天展开时小麦克风仍可录音、松手转文字并发送正确对手、短按/滑开取消、权限延迟授予不遗留麦克风、识别及发送失败、已有麦克风占用不抢占、隐藏子页取消录音通过。未调用真实 ASR/TTS 服务或真机麦克风。
- 隔离服务与手机尺寸 Chrome 验证两位 AI 的转杆、后拉和实际出杆；最后显示的角度、预览目标及服务端击球角度完全一致，暂停期间不执行预览中的一杆，恢复后使用新预览。
- 试玩使用临时存档与测试名字，没有访问真实聊天数据库、调用真实模型或语音服务。真实模型措辞及音色需在小家的现有配置下体验。
