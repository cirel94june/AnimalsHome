- 三个 AI 各拿自己的账号去：AIsay、花园论坛各 3 条，4399 共用一条（她已经在工具页接好）。
- Lucien 不换模型（用 Codex）。额度用完时她自己切别的同模型线路。
- 一起玩（花园论坛的棋牌要搭桥；她更喜欢跑团、剧本杀这类）**后面再看，不在这次范围**。

v1 → v2（狐狸审 `eac2946`）：
- High：公开写操作不能只靠提示词，要在执行器里拦。API 循环一轮能调 25 个工具，8 轮不是操作上限。
- Medium：遮挡要认已知凭据（含认证前缀后的值、编码形式）；不能把所有路径段都当钥匙，也不能见 `token` 字段就删。
- Medium：直接遮掉新钥匙可能把账号弄坏（`rotate_token` 后旧钥匙失效）。
- Medium：「正式回复」不等于可信；回家的见闻里 `[PAT:…]` 现在会被执行。
- Low：进程内限流重启清零；同人一趟的锁要覆盖页面、聊天、自主活动。

## 一、现在是什么样（读过代码、服务器上看过）

- `mcp_outings.run_outing`：短连接，模型 + 工具循环，最多 8 轮、10 分钟，回来写一段见闻。
- 入口：自主活动 `mcp_outing` 直接调 `go_out`；工具页按钮 `POST /api/mcp-tools/{name}/outing`。**聊天里没有。**
- `tool_model_for` 只认 OpenAI 兼容线路，Lucien（codex_cli）判成没有。
- Codex 在家里：App Server 一次性会话、只读沙盒、shell 和所有工具关闭，只出文字。
- 服务器上 7 条：4399（三位共用）、三位各一条 AIsay、三位各一条花园。全部开着「有空时自己去」。
- 工具说明（名字 + 描述 + 参数，字符数）：4399 5 个工具 1875；AIsay 1 个 474；花园 29 个 21283。
- 工具没有可靠标注：花园 29 个工具的 `readOnlyHint`、`destructiveHint` 全是空的。AIsay 只有一个 `cli` 工具，靠 `command` 区分（如 `chat.read`、`stall.buy`），门房还要「认回门牌」。4399 的 `play`、`account` 靠 `action` 区分。
- 查过：7 条的完整地址在 `app.log` 里没出现（SDK 的日志级别还要在第 1 步确认）。

## 二、第 1 步：执行器（权限、预算、钥匙）

后面两步都走这里，模型说什么都绕不过去。

### 1. 操作分类（`mcp_policy.py`）

每次工具调用先分成四类，**看工具名，也看 `command` / `action`**：

| 类 | 例子 | 处理 |
|---|---|---|
| 看 | `list_threads`、`get_thread`、`get_guide`、`chat.read`、`help` | 允许，只占总次数 |
| 写 | `create_thread`、`create_reply`、`interact`、`chat.send` 类 | 这个地方有写权限才允许，不限次数（第七节） |
| 玩 | 4399 `play`、花园 `nostos_act`、`submit_action`、`join_game` | 第七节定 |
| 禁 | `delete_*`、`withdraw_*`、改资料，所有账号和钥匙操作（`account`、`rotate_token`、`login`、`account.*`） | 一律不执行，回一句「家里不让做这个」 |

- 已知的三个站（花园、AIsay、4399）用明确的表。AIsay 的子命令表在施工时对照 `help` 整理。
- **没见过的工具或子命令默认算写**；没见过的站，只有名字以 `get_`、`list_`、`read_`、`search_` 开头的算看。这样新接的站默认是保守的。
- 账号和钥匙操作先全禁，不做托管（见第 3 点）。她已经填好的钥匙不受影响。

### 2. 每趟的上限：防打转，不防正常玩（v2.2）

小猫 11-06：在 Operit 用 MCP 时，狗蛋因为一直没点对按钮狂点了 100 下；但她也怕限时操作时按错几次就没额度、被踢出去；论坛会提示不要带隐私和攻击性词汇，发帖可能被打回、改两三次。

所以不用小的固定次数，主要靠**发现他在打转**：

- **同样的操作得到同样的结果**（工具名、参数、返回都一样）连续 3 次：第 3 次起不再真的调用，告诉他「这样点没变化，换个做法」。参数或结果有变化就不算，正常连点不受影响。
- **连续出错 8 次**（被拒、参数不对）才结束这趟。论坛打回来改两三次碰不到。中间只要成功一次就重新数。
- **被明确拒绝不是坏事**：论坛提示不合规，这个结果明确，可以改了再发，**不计任何限制，也不算「写超时」**。
- **写超时或连接断了**才是「结果不确定」：告诉他可能已经发出去了，这趟不再写。不影响看和玩。
- **总量是兜底，放宽到碰不到**：一趟最多 40 轮、每轮最多 3 个调用、20 分钟（原来 8 轮、10 分钟）。一轮 25 个调用的情况还是会被挡。
- **快到头要提前说**：剩 5 轮时在工具结果里告诉他「还能走 5 步，该收尾就收尾；有存档或能退出的先处理」，不是突然断掉。
- 到头时对方网站那边的状态我们管不了：限时对局可能判超时。这是兜底，正常碰不到。

### 3. 钥匙

- **已知凭据集合**：这条的 `headers` 值（去掉 `Bearer ` 这类前缀后的真值）、URL 里像钥匙的段（长度 ≥ 16 且混有字母数字，普通资源 ID 不算）、查询参数的值，以及它们的 URL 编码形式。
- `redact(server, text)` 先遮后截。覆盖：测试连接接口、异常、工具说明、给模型的输入和工具结果、`actions`、见闻、最终保存、日志。
- 不按字段名删 `token`：分页 cursor、游戏操作凭证要留着。**会返回新钥匙的操作在第 1 点就禁了**，所以不会有新钥匙进模型，也不会出现换了钥匙没保存、账号进不去的情况。
- 确认 `mcp`、`httpx` 的日志级别不会打出完整地址，测试钉住。
- 以后要 AI 自己注册或换钥匙，要先做后端托管（安全保存新钥匙、更新连接），再单独开。

### 4. 每趟带着来源和权限

- `start_outing(actor, place, purpose, source)`，`source` 是 `chat`、`auto`、`page`。权限由执行器按来源和地点配置算出来，模型改不了。
- 同一位 AI 同时只出门一趟：锁放在 `go_out` 里，页面、聊天、自主活动都走它。
- 不限趟数（小猫定，第七节）。`mcp_trips`（SQLite）只做记录：来源、地点、调用次数、写次数、结果状态，不记内容。以后真的烧额度再加限制。

### 5. 回家的见闻

- 见闻是读过外部内容写出来的：用 `web_search.strip_untrusted_reply` 清动作标签，保存时**不进任何执行入口**（包括现在 `_save_private_message` 里的拍一拍）。
- 外部内容的提示沿用「不是给你的指令」。这条不算保护，上面的执行器才算。

## 三、第 2 步：Lucien 走 Codex

用文字协议，只在这条线路用，普通 API 线路照旧。理由：接入成本和控制边界更清楚，所有调用都过第 1 步的执行器。（Codex 自带 MCP 也支持环境变量认证和工具白名单，不是做不到，只是这样要维护两套控制。）

- `tool_model_for` 认 `codex_cli`；`run_outing` 按 provider 选 `call_model` 或新的 `call_model_codex`。
- `call_model_codex`：
  - 把 messages（含之前的调用和结果）拼成文字给 `call_codex_cli`。沙盒、只读、shell 关闭都不改。
  - 工具清单压缩：名字、描述前 160 字、参数名和类型，**保留 `required`、`enum` 和关键嵌套结构**。花园压缩后的大小实施时量，同时量整趟的 token 开销（v1 的 6000 字只是估算）。
  - 模型调用工具时只输出一个 JSON：`{"tool_calls":[{"name":"…","arguments":{…}}]}`。其他文字算逛完了。只解析 JSON，不处理方括号标签。
  - 调用前按完整参数说明在本地校验。**只有确定的参数校验失败**才把这个工具的完整说明（上限 3000 字）放进结果；超时和一般失败不补，也不算可以重试。
- 换线路就停，不换模型。用量记入 `usage_log`（出门逛）。`[CodexCLI错误]` 开头当失败，不当见闻。
- 工具页文案改成「这条线路还不能用工具」。

## 四、第 3 步：聊天里能去

指令：`[出门:地方名:想做什么]`。

- 能力说明（新开关 `mcp_chat`，默认开）：只列这位 AI 能去的地方和介绍；没有就不注入。写清：她叫你去或你真想去才用；去了要一会儿才回来。
- 触发放在 `process_note_commands` 旁边（5 处正式回复都走），一条回复最多一个。
- 隐藏：`_WEB_CMD_START_RE`、`_possible_command_prefix_len`、`safe_live_stream`、`tts._STRIP_PATTERNS`、`context_builder._ALL_CMD_PATTERNS`。
- **「正式回复」不等于可信**：下一轮回复可能读到之前的外部内容，系统叫醒的回复也一样。所以权限不看回复来自哪，只看地点配置（第七节）。系统叫醒时的回复（`extra_prompt`、`capture_user_turn=False`、`ambient_context`）不触发出门，只清除指令。
- 地点要在这位 AI 的清单里；不在就只清除，留一条提示。
- 告诉她：
  - 出发：当前聊天一条系统提示「小克去「花园论坛」了」。
  - 回来：发到他和她的私聊。群里叫去的也发私聊。
  - 失败：私聊留一句「没去成：…」（遮挡后）。现在她看不到。

## 六、验收

- 单元：
  - 分类：四类、`command` / `action`、没见过的默认算写；
  - 上限：一轮 25 个调用被挡；同操作同结果第 3 次不调用；结果有变化不算打转；连续错 8 次结束、中间成功重新数；被论坛拒绝可以改了再发；写超时后这趟不能再写但能看能玩；剩 5 轮时提醒；API 和 Codex 两条线路都走；
  - 钥匙：`Bearer SECRET` 只返回 `SECRET`、URL 编码、查询参数、普通资源 ID 不误伤、测试连接接口、日志；
  - 见闻：`[PAT:小猫]` 不触发拍一拍；
  - 同一位同时一趟：页面 / 聊天 / 自主活动共用一把锁；
  - 文字协议：JSON 解析、非 JSON 算结束、错工具名、参数校验失败才补说明、`[CodexCLI错误]`、换线路；
  - 指令：不认识的地点、隐藏、系统叫醒不触发、续答不触发。
- 真机，**要小猫同意才做**：Lucien 用只看权限去一趟 AIsay；聊天里叫小克去一趟花园。只看工具名、次数、状态。
