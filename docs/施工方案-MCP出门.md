## 一、现在是什么样（读过代码、服务器上看过）

- `mcp_outings.run_outing`：短连接，模型 + 工具循环，最多 8 轮、10 分钟，回来写一段见闻。
- 入口只有两个：自主活动 `mcp_outing`、工具页按钮 `POST /api/mcp-tools/{name}/outing`。**聊天里没有。**
- `tool_model_for` 只认 OpenAI 兼容线路（custom_openai / siliconflow / aipro）。Lucien 是 `Codex-5.6-Sol`（codex_cli），所以判成没有。
- Codex 在家里是：App Server 一次性会话、只读沙盒、shell 和所有工具关闭，只出文字。
- 服务器上 7 条：4399（三位共用）、三位各一条 AIsay、三位各一条花园。全部开着「有空时自己去」。
- 工具说明大小（名字 + 描述 + 参数，字符数）：4399 5 个工具 1875；AIsay 1 个 474；花园 29 个 21283。
- 查过：7 条的完整地址在 `app.log` 里都没出现。

## 二、这次要做的三件事

### 第 1 步：钥匙别漏（先做，后两步都依赖）

AIsay 的钥匙在地址路径里，花园的在 `Authorization` 里。现在这些地方可能漏：

| 地方 | 风险 |
|---|---|
| `go_out` 的 `log.warning(...error)` 和失败事件 `str(error)[:300]` | 连接报错可能带完整地址，写进日志和自主活动记录 |
| `run_outing` 的 `actions`（`name → text[:120]`） | 工具返回的内容进 `idle_events.metadata`，页面能看到 |
| 给模型的 tool 结果和见闻 | 比如 4399 的 `account` 注册、`rotate_token` 会把钥匙直接返回给模型，见闻可能写进聊天，再进 Hub |

改法：
- `mcp_outings.redact(server, text)`：把这条的 URL 路径段（除了常见的 `mcp`、`sse`、`api`）、`headers` 的值替换成 `***`。上面三处都先过它。
- 工具结果里形如 `"token": "…"` 的值也替换（给模型之前就换）：模型不需要拿着钥匙。
- 工具页接口 `url` 字段原样返回给她自己的页面（要能编辑），这次不动；页面有 Cloudflare 登录。

### 第 2 步：Lucien 走 Codex 也能去

不打开 Codex 自带的 MCP：那要把钥匙写进 Codex 配置、打开工具开关，还绕过我们的轮数上限和上面的遮挡。

改成**文字协议**，只在这条线路用，普通 API 线路照旧：
- `tool_model_for` 认 `codex_cli`；`_endpoint` 不变，`run_outing` 按 provider 选 `call_model` 或新的 `call_model_codex`。
- `call_model_codex(model_key, messages, tools)`：
  - 把 messages（含之前的工具调用和结果）拼成文字给 `call_codex_cli`。沙盒、只读、shell 关闭都不改。
  - 工具清单放在提示里。每轮都要带全，所以**要压缩**：名字 + 描述前 160 字 + 参数名和类型。花园从 2.1 万字压到估计 6000 字左右，量过再定。
  - 模型调用工具时只输出一个 JSON：`{"tool_calls":[{"name":"…","arguments":{…}}]}`，每轮最多 3 个。其他文字都算逛完了。
  - 工具名不在清单里：不调用，回一句错误。参数被对方拒绝时，把这个工具的完整参数说明（上限 3000 字）放进结果，下一轮能改。
- 模型输出只解析 JSON，不处理任何方括号标签。工具结果明确标为外部不可信数据。
- 模型线路照 `run_outing` 现有的固定方式，换线路就停，不换模型。
- 用量：`call_codex_cli` 的 meta 记入 `usage_log`（出门逛）。
- 额度用完：`[CodexCLI错误]` 开头的文字当失败，不当见闻。见闻照「失败」处理（第 3 步）。
- 工具页文案改成「这条线路还不能用工具」，不再说「没有能调用工具的模型」。

### 第 3 步：聊天里能去

指令：`[出门:地方名:想做什么]`。

- **能力说明**（`capabilities`，新开关 `mcp_chat`，默认开）：只列这位 AI 能去的地方（`places_for(actor, autonomy_only=False)`）和介绍；没有地方、线路不支持就不注入。说明里写清：她叫你去或你真想去时才用；去了要一会儿才回来；在外面发帖是公开的。
- **触发**：放在 `process_note_commands` 旁边。它正好在 5 处正式回复都走（`routes/chat.py` 3 处、`routes/chatroom.py` 2 处），身份也都在。一条回复最多一个。
- **隐藏**：`_WEB_CMD_START_RE`、`_possible_command_prefix_len`、`safe_live_stream`、`tts._STRIP_PATTERNS`、`context_builder._ALL_CMD_PATTERNS`。
- **执行**：从 `api_outing` 抽出 `start_outing(actor, name, purpose)`，页面和聊天共用，后台跑 `go_out`，不占着聊天。
- **规矩**：
  - 地点要在这位 AI 的清单里，名字空白压缩后比较；不在就只清除，留一条系统提示「想去但不认识这个地方」。
  - 同一位 AI 同时只能出门一趟（现在只按人 + 地方限制，要改）。
  - 每位 AI 聊天触发每小时最多 3 趟（进程内计数）。超了留提示，不去。
  - 只有正式回复能触发。读过外部内容的续答（联网、淘宝）不触发，这些路径本来就不经过 `process_note_commands`，加测试钉住。
- **告诉她**：
  - 出发时当前聊天里一条系统提示：「小克去「花园论坛」了」。
  - 回来：沿用 `go_out` 发到**他和她的私聊**。群里叫去的也发私聊，这次不做回群。
  - 失败：现在只写自主活动记录，她看不到。聊天触发的失败要在私聊留一句「没去成：…」（遮挡后）。
