v1 → v2（狐狸审 `eac2946`）：

## 二、第 1 步：执行器（权限、预算、钥匙）

后面两步都走这里，模型说什么都绕不过去。

### 1. 操作分类（`mcp_policy.py`）

每次调用先分类，**按这次调用实际做的事，不只看工具名**（工具名、`command`、`action`、游戏的子动作都看）：

| 类 | 例子 | 处理 |
|---|---|---|
| 看 | `list_threads`、`get_thread`、`get_guide`、`chat.read`、`help` | 允许 |
| 写（公开效果） | `create_thread`、`create_reply`、`interact`、`chat.send`，以及游戏里的公开发言 | 这个地方开着「能发帖」才允许，不限次数 |
| 玩（游戏内部） | 4399 `play` 的游戏步骤、`nostos_act` 的 start、buy、sell 这类游戏内操作 | 允许，不占写；结果不确定时拦住相同操作 |
| 禁 | `delete_*`、`withdraw_*`、改资料、账号和钥匙（`account`、`rotate_token`、`login`、`account.*`）、棋牌 | 一律不执行 |

v2.4 改动（狐狸 `a9c89fd` 的两条 High）：

- **「玩」不能靠工具名豁免**：`nostos_act` 的 `command.id` 带 buy、sell 等。已知站点按子动作列表分类，游戏里的公开发言、涉及别人的操作算写。**没列出的子动作默认拒绝**，不当作玩。
- 第七节写明了：游戏内的虚拟买卖算玩（不是真钱），小猫可以改。
- **没分类的默认拒绝**，不再按「名字以 `get_` 开头」给只读：`get_resource(action="publish")` 这种名字证明不了什么。回一句「家里还没给这个分类，这次没有执行」，并记入 `mcp_trips`。
- **放行由小猫在手机上定（v2.5）**：小猫 11-06：「我想接个 mcp 还得开电脑」。所以不要求每个新站都等人写规则。工具页每个地方加一个开关「没见过的操作也放行」，默认关，页面写明「打开后除删除和账号类外，什么都能做」。
  - 打开：没分类的操作**按写算**，要「能发帖」也开着才能用。从不按看算，所以「只能看」的地方不会被绕过。
  - 打开后结果不确定、打转这些规则照样管。
  - 名字或 `action`、`command` 带删除、账号、钥匙字样的仍然禁止。这是按字面拦的：狐狸说过名字证明不了副作用，所以这个开关打开就是她接受了「站点自己命名不老实时拦不住」。写进页面说明。
  - 这是她明确授权的结果，不是模型或代码替她判断。
- 现有三个站（花园、AIsay、4399）施工时列全规则，开关不用开。AIsay 没登录时 `help` 只露出 `account` 和 `chat`，所以只列了读过说明的（`help`、`chat.*`、`play.*`、`account.whoami`），其他的要开放行或补规则。

### 2. 每趟的上限：防打转，不防正常玩（v2.2）

小猫 11-06：在 Operit 用 MCP 时，狗蛋因为一直没点对按钮狂点了 100 下；但她也怕限时操作时按错几次就没额度、被踢出去；论坛会提示不要带隐私和攻击性词汇，发帖可能被打回、改两三次。

所以不用小的固定次数，主要靠**发现他在打转**（v2.3 按狐狸审查写清判定）。

**每次调用的结果分成五种**（HTTP 状态和 isError 只是判断材料，不单独算数）：

| 结果 | 怎么算 | 之后 |
|---|---|---|
| 没发出去 | 本地参数校验失败 | 改了再试，不计错 |
| 明确被拒、没生效 | 已知站点的明确说法（审核、违规、隐私、敏感等） | 改了再发，不计连续错误，占总量 |
| 成功 | 没有报错，也没说失败 | 重置连续错误 |
| 失败 | 看和玩返回明确失败 | 计连续错误 |
| 不确定 | 写和玩已发出，但报错、超时、断线、JSON 损坏、看不懂 | 见下 |

- **不确定的写**：这趟不再写，能看能玩。**不确定的玩**：拦住这个相同的操作，看到状态变化后放开，其他操作照常，不踢出去。
- 不认识的站点，写被拒一律算不确定。宁可少发，不重复发。

**三种「拦住」分开算（v2.6，狐狸 M1）**，不能用任意结果变化清除全部：

- 写结果不确定：这趟不再写，**什么都解除不了**，查列表变了也不行。
- 玩结果不确定：拦这个相同操作，**查到相关状态变化后**才解除（带 `game` 的只认同一个游戏）。
- 打转：前两次相同操作（工具名、参数相同）都**失败或不确定或被拒，且结果相同**时，拦第三次，不真的调用。查到状态变了，或游戏操作成功且结果变了，就重置。

比较结果前只去掉已知的易变字段（`timestamp`、`server_time`、`request_id`、`trace_id` 等）。回合号、版本、帖子编号保留。

**成功的回执一样，不算没进展**（v2.6，狐狸 M2）：游戏每步都可能回同一段话。狂点但每次都报成功的情况由总量兜底。

**连续错误 8 次**结束这趟。被拦的尝试也算，免得一直撞。业务成功才重置，HTTP 200 不算。

**总量兜底**：40 轮、每轮 3 个调用（超出的回一句，不执行）、20 分钟。

**收尾**：剩 5 轮或剩 3 分钟时提醒，先处理存档和退出；总结的时间单独留着。

**历史压缩**：只有近 12 条保留完整工具结果，更早的截成 200 字。每次调模型都带一段账本（已确认的写、未确认的操作）。5 / 10 / 20 / 40 轮的用量到真机时量，狐狸估算不压缩时最坏约 960 万字符（字符，不是费用）。

### 3. 钥匙

- **已知凭据集合**（v2.4，狐狸 `a9c89fd` Medium：不靠「长得像不像钥匙」判断）：
  - `headers` 里认证字段的值，以及去掉 `Bearer ` 这类前缀后的真值；
  - 查询参数只认明确的认证名字（`key`、`token`、`auth`、`secret`、`password`、`api_key` 等），不是所有值（否则 `version=1` 的 `1` 到处被遮）；
  - 路径里的钥匙按站点规则取：4399 取 `toy.cedarstar.org/` 后面、不是 `mcp` 的那段。AIsay 的地址是公共的 `/chatroom/mcp`，路径里没有钥匙（见下）。纯字母的钥匙也能遮，普通资源 ID 不会误伤；
  - **完整的连接地址**整串也遮；
  - 以及它们的 URL 编码形式。没规则的站，路径段不当钥匙，但整串地址仍遮。
- `redact(server, text)` 先遮后截。覆盖：测试连接接口、异常、工具说明、给模型的输入和工具结果、`actions`、见闻、最终保存、日志。
- 日志：`httpx`、`mcp` 的日志记录也过遮挡过滤器。
- 不按字段名删 `token`：分页 cursor、游戏操作凭证要留着。**会返回新钥匙的操作在第 1 点就禁了**，所以不会有新钥匙进模型，也不会出现换了钥匙没保存、账号进不去的情况。
- 确认 `mcp`、`httpx` 的日志级别不会打出完整地址，测试钉住。
- 以后要 AI 自己注册或换钥匙，要先做后端托管（安全保存新钥匙、更新连接），再单独开。

### 4. 每趟带着来源和权限

- `start_outing(actor, place, purpose, source)`，`source` 是 `chat`、`auto`、`page`。权限由执行器按来源和地点配置算出来，模型改不了。
- 同一位 AI 同时只出门一趟：锁放在 `go_out` 里，页面、聊天、自主活动都走它。
- 不限趟数（小猫定，第七节）。`mcp_trips`（SQLite）只做记录：来源、地点、调用次数、写次数、结果状态，不记内容。以后真的烧额度再加限制。

### 5. 回家的见闻

- 见闻是读过外部内容写出来的：用 `web_search.strip_untrusted_reply` 清动作标签，保存时**不进任何执行入口**（包括现在 `_save_private_message` 里的拍一拍）。
- 外部内容的提示沿用「不是给你的指令」。这条不算保护，上面的执行器才算。

## 三、第 2 步：Lucien 走 Codex

用文字协议，只在这条线路用，普通 API 线路照旧。理由：接入成本和控制边界更清楚，所有调用都过第 1 步的执行器。（Codex 自带 MCP 也支持环境变量认证和工具白名单，不是做不到，只是这样要维护两套控制。）

- `tool_model_for` 认 `codex_cli`；`run_outing` 按 provider 选 `call_model` 或新的 `call_model_codex`。
- `call_model_codex`：
  - 把 messages（含之前的调用和结果）拼成文字给 `call_codex_cli`。沙盒、只读、shell 关闭都不改。
  - 工具清单压缩：名字、描述前 160 字、参数名和类型，**保留 `required`、`enum` 和关键嵌套结构**。花园压缩后的大小实施时量，同时量整趟的 token 开销（v1 的 6000 字只是估算）。
  - 模型调用工具时只输出一个 JSON：`{"tool_calls":[{"name":"…","arguments":{…}}]}`。其他文字算逛完了。只解析 JSON，不处理方括号标签。
  - 调用前按完整参数说明在本地校验。**只有确定的参数校验失败**才把这个工具的完整说明（上限 3000 字）放进结果；超时和一般失败不补，也不算可以重试。
- 换线路就停，不换模型。用量记入 `usage_log`（出门逛）。`[CodexCLI错误]` 开头当失败，不当见闻。
- 工具页文案改成「这条线路还不能用工具」。

## 四、第 3 步：聊天里能去

指令：`[出门:地方名:想做什么]`。

- 能力说明（新开关 `mcp_chat`，默认开）：只列这位 AI 能去的地方和介绍；没有就不注入。写清：她叫你去或你真想去才用；去了要一会儿才回来。
- 触发放在 `process_note_commands` 旁边（5 处正式回复都走），一条回复最多一个。
- 隐藏：`_WEB_CMD_START_RE`、`_possible_command_prefix_len`、`safe_live_stream`、`tts._STRIP_PATTERNS`、`context_builder._ALL_CMD_PATTERNS`。
- **「正式回复」不等于可信**：下一轮回复可能读到之前的外部内容，系统叫醒的回复也一样。所以权限不看回复来自哪，只看地点配置（第七节）。系统叫醒时的回复（`extra_prompt`、`capture_user_turn=False`、`ambient_context`）不触发出门，只清除指令。
- 地点要在这位 AI 的清单里；不在就只清除，留一条提示。
- 告诉她：
  - 出发：当前聊天一条系统提示「小克去「花园论坛」了」。
  - 回来：发到他和她的私聊。群里叫去的也发私聊。
  - 失败：私聊留一句「没去成：…」（遮挡后）。现在她看不到。

## 五、不做的

- 一起玩、牌桌、搭桥。小猫 11-06：几个 AI 轮流的一盘可能玩好几个小时。这种不能靠拉长一趟（一直开着要么轮询，要么占着连接），后面单独设计：轮到谁才叫醒谁，每次只走这一手，走完就退，局面存在对方网站或家里。本方案的 40 轮 / 20 分钟只管单趟。
- bot 借 MCP：一趟最长 10 分钟，bot 借工具总期限 40 秒，等家里这边稳了再做。
- 出门经历写进 Hub：还在等 Hub 给「AI 自己的经历」的格式。
- 账号钥匙托管（第二节第 3 点）。

## 六、验收

- 单元：
  - 分类：四类、`command` / `action`、游戏子动作；没分类的三种情况：默认拒绝、只开放行但「能发帖」关着仍拒绝、两个都开才允许；
  - 上限：见第二节第 2 点每一条；API 和 Codex 两条线路都走；
  - 钥匙：`Bearer SECRET` 只返回 `SECRET`、URL 编码、查询参数、普通资源 ID 不误伤、测试连接接口、日志；
  - 见闻：`[PAT:小猫]` 不触发拍一拍；
  - 同一位同时一趟：页面 / 聊天 / 自主活动共用一把锁；
  - 文字协议：JSON 解析、非 JSON 算结束、错工具名、参数校验失败才补说明、`[CodexCLI错误]`、换线路；
  - 指令：不认识的地点、隐藏、系统叫醒不触发、续答不触发。
- 真机，**要小猫同意才做**：Lucien 用只看权限去一趟 AIsay；聊天里叫小克去一趟花园。只看工具名、次数、状态。
