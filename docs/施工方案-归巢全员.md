# 施工方案：归巢模式让每位 AI 都能进（2026-10-29）

## 小猫的需求
- 地铁上信号差、不总开 VPN。想知道归巢怎么用。（已答：归巢管的是「服务器连不上」，不管「没信号」；入口是 App 起始页的「🏠 归巢模式」。）
- 归巢要让每位 AI 都能进：小克、Lucien、狗蛋，以及以后在空座位上接的 DeepSeek、Grok、Kimi 等。

## 现状（原作者的设计）
- 服务器 `homecoming/snapshot.py` 打一份快照给手机，里面只有两位伴侣：
  - `main` = 小克，私聊时间线叫 `main_private`。
  - `second` = Lucien，私聊时间线叫 `companion_private`。
  - 外加一个群聊时间线 `group`。
- 只有设置页 `custom_model_routes` 里 https 的线路才会带到手机上，座位自己的 API（`seat_model_routes`）不带。Lucien 平时用的 Codex 不是这种线路，所以进归巢后要在选择框里给他挑一条能带走的线路。原作者已经做了「每位伴侣选线路和模型」。
- 手机端：
  - `HomecomingIdentityRepository` 只认 main 和 second。
  - `HomecomingGroupTurnCoordinator` 要求群里正好两位。
  - 界面只有三个固定选项。
  - 本地数据库没有写死人数的约束，可以扩展。
- 回传：`return_importer.py` 把 main 映射到 aion、second 映射到 connor，其他的不认。

## 改法
保留 main 和 second 两个旧名字，这样已经装着的旧 App 和旧快照照样能用。新增座位 `ai3` 到 `ai6`：

1. **服务器快照**（Python，可以本机测）
   - `identity.companions` 加上已启用的座位：`ai3` 到 `ai6` 各自的名字、人设、声音。另外加一个 `roster`，列出每位的 owner、时间线和名字，手机按它来画界面。
   - 新时间线 `seat_private:<座位>`：座位私聊（`chatroom_rooms.type='seat_1v1' AND actor=?`）最近的消息。
   - `group` 时间线带上群成员：小克、Lucien，以及 `_group_seat_members()` 里的座位。
   - 线路：`seat_model_routes`（座位自己的 API）也做成描述和加密密钥带到手机，复用 `crypto.py` 现有的加密方式。
   - 记忆：座位的记忆在 Hub 上，归巢时连不上 Hub，所以第一版座位只带人设和最近聊天，不带记忆。
2. **手机端**（Java 和 assets，只能靠 GitHub Actions 打包和跑单元测试）
   - Identity 认 roster 里的 owner；没有 roster 时退回旧的两位。
   - 会话选择器按 roster 生成，每位一个私聊，再加一个群聊。
   - 群聊轮流回复：人数从「正好 2 位」放宽为「至少 1 位」，顺序按 reply_order，座位排在后面。
   - 每位 AI 各自选线路和模型，沿用原作者按 owner 存的偏好。
3. **回传合并**（Python）
   - `seat_private:<座位>` 合并回那位座位的 seat_1v1 房间；没有就新建，复用 `_get_or_create_seat_room`。
   - 群聊里座位的发言，sender 写座位 id。
4. 测试：Python 端补快照、回传测试；Java 端补 Identity、群轮流、界面契约测试，由 CI 跑。
5. 交给 Codex 审 → 部署服务器 → 新 APK 放 `/uploads/AionsHome.apk` → 小猫装上，在手机上试一次进入和回传。

## 第一版不做的（已告诉小猫）
- 座位在归巢里没有长期记忆（在 Hub 上），也不能定提醒或闹钟（手机日程只认两位，会被安全拦下），回来后也不合并。
- 座位不朗读：还没有自己的声音，不借小克的。
- 群聊里别的 AI 的发言，对模型来说仍然是「assistant」，不带名字（原作者两人时就是这样）。人多了可能分不清谁说的，以后再改。
