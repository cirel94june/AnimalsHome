# 施工方案：监控 / 定位发现情况时叫谁（含狗蛋等座位）

2026-10-21 小猫的要求：
- 摄像头「智能」模式不要固定分工（「小克管情绪也好奇怪」），要更智能。
- 出门 / 回家（定位变化）也要「随机，智能一点」，不再固定叫小克。
- 狗蛋（以及启用的座位 4～6）都要能被叫来。

## 现状

- 摄像头：设置里 `wake_mode` = aion / connor / smart。smart 时哨兵按固定分工选 main_ai / second_ai / both（`camera.build_sentinel_dispatch_policy`）。唤醒走 `_wake_core_targets`，只认 aion / connor。
- 定位：`location._notify_sentinel` 只判断要不要叫，叫的话固定 `_call_core_location`（小克）。

## 改法

1. **候选名单** `wake_roster()`：小克、Lucien，加上已启用、有人设、有模型的座位（`seat_chat.check_ready` 通过）。每人带名字和「上次被叫来的时间」（从监控日志的 `final_wake_targets` 里找）。
2. **智能挑人规则**（摄像头和定位共用，替换原来的固定分工）：
   - 她明确点名谁就叫谁；
   - 正在和谁聊这件事、最近是谁在跟进同一件事，就保持连续；
   - 都不明显时，参考谁最近和她聊得多、谁很久没被叫来；仍然拿不准就用系统给的「随机建议人选」（偏向最久没被叫来的人随机抽）；
   - 只有明显危险、健康异常、情绪崩溃这类情况才同时叫两个或更多人；
   - 不按事情类型固定分给谁。
   - 输出 `wake_target`：一个人的 id，或用逗号分隔的几个 id；兼容旧值 main_ai / second_ai / both。不在名单里的 id 丢掉；全丢光了就用随机建议人选。
3. **摄像头设置**：`wake_mode` 可选值加上 ai3～ai6（固定叫这位座位）。设置页下拉框列出已启用的座位。
4. **定位设置**：新增 `location_wake_mode`（存在摄像头配置里），可选 smart / aion / connor / ai3～ai6，默认 smart。哨兵判断要叫时，smart 按上面的规则挑人。
   - 叫小克：照旧走 `_call_core_location`（行为不变）。
   - 叫 Lucien / 座位：走摄像头的唤醒流程（把位置事件作为监控记录、不带截图）。
5. **叫座位**：`_wake_core_targets` 认座位；座位去她最近说话的地方（群或 TA 私聊，见 §54），用 TA 的人设和模型（`_generate_seat_reply`，附上截图），提示词与 Lucien 的唤醒提示同类（多久没说话、叫醒原因、监控记录、设备动态、位置）。座位没准备好时房间里会有「没能回复」记录，不换人。
6. 哨兵失败的保守回退：摄像头沿用原逻辑（固定模式按设置，smart 回退到随机建议人选）；定位分析失败时照旧默认要叫，叫谁按定位设置（smart 用随机建议人选）。

## 不改

- 要不要叫（call_core）的判断规则不变。
- 小克、Lucien 被叫来后的回复流程不变。
