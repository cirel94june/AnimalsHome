# 给 Memory Hub 窗口：记忆召回改进建议（借鉴 IB 机 V3.0「AGB」）

> 来源：AionsHome 窗口，2026-10-11。小猫同意两边一起推进。
> 这是**建议**，不是施工方案；Hub 侧请按《施工必读》写方案、等小猫同意后再动。
> 参考：Sui-IB/InternalBeyond-Mobile V3.0 README「Memory · AGB 记忆系统」（只读了说明，未读其代码）。

## 现状（读 Hub main 代码核对过）

- `context(mode="incremental")` 每轮都调 `memory_ops.recall(query=user_message, top_k=5)`，
  **没有相关度门槛**：寒暄（"嗯嗯""晚安"）也会塞 5 条「相关记忆」。
- recall 打分 = 向量 0.6 + 情绪 0.15 + 时间 0.1 + 重要度 0.15，排序后取前 top_k，最低分不设下限。
- 前端看不到「这轮想起了哪几条、为什么」，也没法当场说「这条不相关 / 过时了」。

## 建议（按价值排）

### 1. 召回「少而准」：加门槛，宁缺毋滥

IB 的规则（可直接对照）：
- 寒暄、短应答不翻库；
- 过门槛：标签在话里出现 / 字面命中 / 语义够近，三者之一；
- 过门的按 相关度 × 新旧 × 重要度 排序，**每轮最多 1～3 条**；
- **低于最相关那条一半的不给**；一条都不合适就不给；
- 用户明说「还记得」「你说过」时门槛放宽；
- 话里有时间（上周、去年三月）时，那段时间的记忆排前。

验收建议：用小猫真实对话抽样（寒暄 / 提到旧事 / 提到人名 / 带时间），对比改前改后注入了什么。

### 2. 「回望」：每轮想起了什么，可查可纠

- `context(incremental)` 的返回里附上**这轮注入的记忆 id + 命中理由**（标签 / 字面 / 语义 / 时间）。
- AionsHome 会在 AI 回复旁显示「想起了 N 条」，点开可标「不相关」「过时」：
  - 「过时」→ 调现有的 supersede / correct 路径；
  - 「不相关」→ 记一条召回反馈（这条记忆 × 这类话不该被想起），供门槛/打分调整。
- 需要 Hub 提供：返回结构里的 id 与理由；一个接收「不相关」反馈的接口（MCP 或 REST）。

### 3. 核心档案改动先确认（对接 Profile 层与「人设种子+生长」）

- AI（或后台）要写入 / 修改**核心级**档案条目（IB 叫 always 级，对应 Hub 的 Profile 核心 / 锚点级）时，
  不直接落库，先生成一张**待确认卡**：写入 / 降级为普通 / 不写；小猫点了才算。
- 普通条目照旧直接写。
- 这和 AionsHome 待办 6「人设种子+生长（小步、有证据、可否决）」是同一个交互，建议两边共用一套「待确认」接口。

### 4. 可以顺带考虑的

- **脉络**：反复出现的事串成一条线，小猫点「同意」才成立；之后想起其中一条时连同这条线的观察一起给。
  （和 continuity 方案里的 OpenThread 接近。）
- **可见范围更细**：除了 shared / per_ai，再支持「仅指定几位 / 排除指定几位」。

## AionsHome 侧会配合做的

- 第 2 条的显示和按钮（Hub 返回 id 和理由后接）；
- 第 3 条的确认卡界面（Hub 提供待确认列表和确认接口后接）。
